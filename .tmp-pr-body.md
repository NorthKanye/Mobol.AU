## Why row 03 is JS-driven instead of CSS-keyframed

Rows 01 and 02 use long single-cycle CSS `@keyframes` (18s for builder, scripted timeline for chat). I prototyped row 03 the same way first — six stacked layers crossfading on a 28s master clock — but each branding stage holds different content (six swatches dropping in at 150ms each, then six color-namings at 550ms each is structurally different from one ruler that grows for 1.7s). Forcing every stage into equal slices made some beats feel rushed and others padded. The grid version lets each beat breathe at its own pace via `await wait(ms)` in an async loop, with `cancelled` flag guarding against unmount-mid-stage.

The scanner rectangle that slides between cells is JS-positioned via `getBoundingClientRect` rather than fixed keyframe waypoints — re-laid-out on resize, no manual coordinate math per breakpoint.
